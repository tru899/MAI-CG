# Лабораторная работа 4

**Вариант 7 — тор.** Выполнено базовое задание (оценка 4): карта теней для направленного
источника света (солнца), построенная каждый кадр динамическим рендерингом. Дополнительное задание
(тень от точечного или прожекторного источника) не делалось.

## Условие

К сцене из лабораторной работы 3 (тор и пол с текстурами, камера, источники света) добавить карту теней:
каждый кадр рисовать глубину сцены с точки зрения солнца в отдельное изображение с помощью
динамического рендеринга (Vulkan 1.3, без `VkRenderPass` и `VkFramebuffer`), а в основном
фрагментном шейдере получать «затенение» через `sampler2DShadow` и сэмплер со сравнением глубины.

| Требование | Где в интерфейсе | Где в коде |
|---|---|---|
| Карта теней рисуется каждый кадр динамическим рендерингом | — | `recordShadowPass` (`vkCmdBeginRendering`, `vkCmdEndRendering`) |
| Новый конвейер с динамическим рендерингом и единственным вершинным шейдером | — | `shaders/shadow.vert`, `graphics::createDepthPipeline`, `vk_shadow_pipeline` |
| Солнце: ортографическая проекция и LookAt | **Shadows → Covered area**, **Light distance** | `computeShadowViewProjection`, `math::Matrix4::look_at` |
| `VkSampler` со сравнением глубины, оператор «меньше» | — | `createShadowMap` (`compareEnable`, `compareOp = VK_COMPARE_OP_LESS`) |
| `sampler2DShadow` в основном фрагментном шейдере | — | `shaders/model.frag` (`shadowFactor`) |
| Площадь, которую покрывает ортографическая матрица, и сдвиг глубины в интерфейсе | **Shadows → Covered area**, **Depth bias (constant / slope)** | `shadow`, `vkCmdSetDepthBias` |
| Пол, на который падает тень | **Floor** | как в лабораторной работе 3 |

## Как это устроено

- **Два прохода за кадр.** Сначала `recordShadowPass` рисует тор и пол с точки зрения солнца только в
  глубину, затем основной проход рисует сцену как раньше. Оба прохода записываются в один буфер команд.
- **Карта теней.** Изображение глубины `D32_SFLOAT` (если нет, `D16_UNORM`) размером 4096 × 4096 с
  использованием «вложение глубины + сэмплируемое изображение». Формат выбирается по возможностям
  устройства (`graphics::findShadowMapFormat`).
- **Динамический рендеринг.** Пока нет `VkRenderPass`, который сам менял бы layout изображения, это
  делают барьеры (`transitionShadowMap`): перед проходом `UNDEFINED → DEPTH_STENCIL_ATTACHMENT_OPTIMAL`,
  после него `DEPTH_STENCIL_ATTACHMENT_OPTIMAL → SHADER_READ_ONLY_OPTIMAL` с ожиданием записи глубины
  перед чтением во фрагментном шейдере. Конвейер знает только формат глубины
  (`VkPipelineRenderingCreateInfo`), цветовых вложений нет.
- **Матрица солнца.** «Камера солнца» стоит в точке `центр − направление · Light distance` и смотрит в
  центр сцены (LookAt). Ортографическая проекция имеет размер `2 · Covered area` по x и y; всё, что
  вне этой области, считается освещённым. Глубина лежит в диапазоне [0, 1].
- **Отсечение передних граней и сдвиг глубины.** При рисовании карты отсекаются грани, обращённые к
  солнцу: в карте остаётся задняя сторона замкнутого тела, и освещённая сторона не затеняет сама себя.
  Остаточное самозатенение убирает динамический сдвиг глубины `vkCmdSetDepthBias`
  (постоянная и наклонная составляющие, значения из интерфейса). Слишком большой сдвиг оторвёт тень от
  объекта, слишком маленький даст полосатые артефакты.
- **Сэмплер.** Билинейная фильтрация вместе со сравнением даёт аппаратное усреднение 2 × 2 результатов
  сравнения (мягкий край тени). Адресация `CLAMP_TO_BORDER` с белой рамкой. Если формат не поддерживает
  линейную фильтрацию, берётся `NEAREST` (жёсткий край).
- **Шейдеры.** Вершинный шейдер основного прохода дополнительно считает положение точки в системе
  координат солнца (`shadow_view_projection · мировая позиция`). Фрагментный делит на `w`,
  переводит x, y в [0, 1] и сэмплирует карту: результат 1.0 (свет доходит) или 0.0 (тень) умножает
  вклад направленного источника. Ambient и точечные и прожекторные источники тень не получают.
- **Дескрипторы.** В наборе сцены (`set = 0`) появился `binding = 3`: изображение глубины и
  сэмплер со сравнением. Для прохода теней есть отдельный набор с одним uniform-буфером (матрица
  солнца) и pipeline layout `[набор теней, набор материала]`: набор материала (с динамическим буфером
  матриц моделей) используется тот же. Размер `SceneUniforms` вырос до 208 байт (std140, проверяется
  `static_assert` в `shader_data.hpp`).

## Особенности для macOS (MoltenVK)

- Нужен Vulkan 1.3: экземпляр создаётся с `require_api_version(1, 3, 0)`, устройство должно
  поддерживать функцию `dynamicRendering`. Подходит Vulkan SDK 1.4.x (в нём MoltenVK с Vulkan 1.3 и выше).
  Если SDK старше, программа пишет в консоль, что нужен Vulkan 1.3, и завершается.
- `VK_KHR_portability_enumeration` и `VK_KHR_portability_subset` включает vk-bootstrap
  автоматически.
- Формат карты теней и возможность линейной фильтрации проверяются по возможностям устройства, а не
  предполагаются.
- Вне карты теней результат не зависит от цвета рамки сэмплера: выход за пределы проверяется в
  шейдере явно.
- Не используются возможности, которых нет в Metal и подмножестве портабельности: зажим глубины,
  `depthBiasClamp` (всегда 0), веера треугольников.
- Для карты теней нужно 64 МБ видеопамяти; сэмплеров на стадию два (лимит Metal 16).

## Сборка и запуск (macOS)

Нужны Xcode Command Line Tools, CMake, Ninja и Vulkan SDK (с `glslc`). При первой
настройке CMake скачивает GLFW, vk-bootstrap, VMA, ImGui и stb, поэтому нужны интернет
и `git`.

Все команды выполняются **из папки лабы**: шейдеры и текстуры загружаются по
относительным путям `shaders/*.spv` и `textures/`.

```bash
source ~/VulkanSDK/<версия>/setup-env.sh
cmake --preset debug
cmake --build build-debug --parallel
./build-debug/vulkan-starter-app
```

Шейдеры из папки `shaders` компилируются в SPIR-V автоматически при сборке (добавлен
`shadow.vert`).

## Что проверить после сборки

1. В окне **Lab 4: Shadow mapping** открыт раздел **Shadows (directional light)**: тор отбрасывает
   тень на пол. Тень двигается вместе с анимацией тора и при изменении направления света
   (**Directional light → Direction**).
2. **Enabled** выключает тени (шейдер возвращает 1.0).
3. **Covered area** уменьшает или увеличивает область карты: при малом значении тень обрезается по
   границе области, при большом край тени становится грубее.
4. **Depth bias**: при нулевых значениях на освещённых частях тора могут появиться полосы, при
   больших тень отрывается от объекта.
5. Остальное из лабораторной работы 3 (текстуры, вобблинг, источники света, их визуализация,
   камера) работает как раньше.

## Система координат

- +X вправо, +Y вниз, +Z вглубь экрана; «вверх» — это −Y, нормаль пола (0, −1, 0);
- после проекции x, y ∈ [−1, 1], глубина ∈ [0, 1] (как в Vulkan);
- матрица камеры `T · Ry · Rx · Rz`, матрица вида — обратная к ней:
  `V = Rz(−z) · Rx(−x) · Ry(−y) · T(−позиция)`; отрицательный поворот по X наклоняет камеру вниз;
- «камера солнца» использует то же пространство вида (+X вправо, +Y вниз, +Z вперёд): матрица
  `Matrix4::look_at(eye, target, down)` для `eye = центр − направление · расстояние`, «низ» — мировое +Y;
- модель: `M = T · Rz · Ry · Rx · S`, нормали преобразуются матрицей `Rz · Ry · Rx · S⁻¹`;
- векторы-столбцы: `p' = P · V · M · p`; матрицы хранятся по столбцам, как `mat4` в GLSL;
- лицевая грань — обход по часовой стрелке, задние грани отсекаются;
- направление источника света — куда он светит;
- текстурные координаты: (0, 0) — левый верхний угол картинки; у тора u идёт вдоль
  кольца, v — вокруг трубки; у пола v = 0 на дальнем от камеры крае (+Z), поэтому
  картинка лежит верхом от зрителя и не отзеркалена.
