## Условие

Добавить к сцене из лабораторной работы 2 текстуры: картинки загружаются из файлов,
становятся текстурами и через текстурные координаты вершин и сэмплер накладываются на
объекты вместо сплошного цвета и цветов вершин. Свойства моделей лежат в одном
динамическом uniform-буфере, вершины и индексы — в памяти GPU (VRAM).

## Текстуры

При запуске программа загружает все картинки из папки `textures/` (`.png`, `.jpg`,
`.jpeg`, `.bmp`, `.tga`, `.gif`) в порядке имён. Каждая картинка — отдельный материал
со своим набором дескрипторов, в выпадающем списке **Texture** она показана именем
файла. Чтобы добавить свою, положите файл в `textures/` и перезапустите программу.
Имена файлов — латиницей: шрифт интерфейса не содержит кириллицы.

- Картинка любого размера переводится в RGBA8 и хранится в формате
  `R8G8B8A8_SRGB`: при выборке GPU переводит цвет из sRGB в линейное пространство, где
  считается освещение. Размер ограничен staging-буфером в 64 МБ (до 4096 × 4096).
- По умолчанию тору достаётся первая текстура по имени, полу — вторая.
- **Tiling** — сколько раз текстура повторяется вдоль u и v (сэмплер в режиме
  `REPEAT`). У тора повторов по u целое число, иначе на стыке кольца будет шов.
- В папке лежат две картинки: `cat.jpg` (по умолчанию на торе) и `cat_white.jpg`
  (на полу).
- Тор по умолчанию повёрнут на −120° вокруг X (в лабораторной работе 2 было 60°):
  форма та же, тор симметричен, но к камере обращена другая сторона трубки — та, где
  на `cat.jpg` морда кота.

## Как это устроено

- **Вершина:** позиция, нормаль и текстурные координаты `uv` (атрибут 2, `vec2`).
  У тора вершин `(segments + 1) × (sides + 1)`: первый столбец и первая строка
  повторены в конце с `u = 1` и `v = 1`. Без этого последняя полоса треугольников шла
  бы от `u ≈ 1` к `u = 0` и сжала бы в себя всю текстуру задом наперёд.
- **Наборы дескрипторов:** `set = 0` — сцена, как в лабораторной работе 2 (uniform-буфер
  и storage-буферы источников). `set = 1` — материал: `binding = 0` — динамический
  uniform-буфер со свойствами моделей, `binding = 1` — пара «изображение + сэмплер».
  Таких наборов столько же, сколько текстур, и все ссылаются на один uniform-буфер.
- **Динамический uniform-буфер:** массив `ModelUniforms` (тор — индекс 0, пол — 1).
  Шаг между элементами — `sizeof(ModelUniforms)` = 160 байт, округлённый вверх до
  `minUniformBufferOffsetAlignment` устройства. При отрисовке модели привязывается
  набор её текстуры, а сдвиг `индекс × шаг` передаётся в `vkCmdBindDescriptorSets`.
- **Push-константы:** `SamplingEffect` (16 байт, фрагментный шейдер) — флаг вобблинга,
  время, амплитуда и частота. Тор получает настройки из интерфейса, пол — нули.
- **VRAM:** вершинные и индексные буферы тора, пола и визуализации источников создаются
  без доступа с CPU. Загрузка идёт через staging-буфер в 64 МБ (заполняется подряд, как
  линейный аллокатор), свой пул командных буферов и забор (fence): данные копируются в
  staging, записываются `vkCmdCopyBuffer` / `vkCmdCopyBufferToImage` с барьерами,
  буфер команд отправляется в очередь, CPU ждёт забор. Текстуры и пол загружаются
  при запуске. Тор — при изменении параметров сетки, визуализация источников — каждый
  кадр, в `render()` после ожидания забора кадра.
- **Сэмплер:** билинейная фильтрация, адресация `REPEAT`, один MIP-уровень.
- **Вобблинг:** UV сдвигаются синусоидами
  `uv + A · (sin(2π·f·v + t), sin(2π·f·u + t))`. Красный, зелёный и синий каналы
  выбираются из трёх точек, разнесённых на `A/2` по направлению, которое вращается со
  временем. Результат умножается на оттенок `0.65 + 0.35 · cos(t + сдвиг канала)`,
  который меняется со временем. Частота `f` — целое число волн на один повтор
  текстуры: тогда при целом **Tiling** волна совпадает на стыках кольца и трубки тора.

## Сборка и запуск (macOS)

Нужны Xcode Command Line Tools, CMake, Ninja и Vulkan SDK (с `glslc`). При первой
настройке CMake скачивает GLFW, vk-bootstrap, VMA, ImGui и stb, поэтому нужны интернет
и `git`.

Все команды выполняются **из папки лабы**: шейдеры и текстуры загружаются по
относительным путям `shaders/*.spv` и `textures/`.

```bash
source ~/VulkanSDK/<версия>/setup-env.sh
cmake --preset debug
cmake --build build-debug --parallel
./build-debug/vulkan-starter-app
```

Шейдеры из папки `shaders` компилируются в SPIR-V автоматически при сборке.

## Как это проверено

- Сборка на macOS (Vulkan SDK 1.4.363, MoltenVK): в коде лабы нет предупреждений
  компилятора.
- Запуск без окна в Linux-контейнере (Xvfb, программный Vulkan Mesa lavapipe) со слоями
  валидации, включая проверку синхронизации (`VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT`).
  Сценарий: стартовые текстуры, включение вобблинга, смена текстур и Tiling, пересборка
  сетки тора, добавление 40 точечных источников (рост буфера визуализации),
  ортографическая проекция. Кадры совпадают с ожидаемыми, ошибок валидации в коде лабы
  нет.
- Проверка синхронизации на каждом кадре сообщает `SYNC-HAZARD-WRITE-AFTER-READ` для
  `vkCmdBeginRenderPass`: у render pass стартового кода нет зависимости от получения
  картинки swapchain. Это стартовый код, сообщение есть и в лабораторной работе 2.

## Система координат

- +X вправо, +Y вниз, +Z вглубь экрана; «вверх» — это −Y, нормаль пола (0, −1, 0);
- после проекции x, y ∈ [−1, 1], глубина ∈ [0, 1] (как в Vulkan);
- матрица камеры `T · Ry · Rx · Rz`, матрица вида — обратная к ней:
  `V = Rz(−z) · Rx(−x) · Ry(−y) · T(−позиция)`; отрицательный поворот по X наклоняет камеру вниз;
- модель: `M = T · Rz · Ry · Rx · S`, нормали преобразуются матрицей `Rz · Ry · Rx · S⁻¹`;
- векторы-столбцы: `p' = P · V · M · p`; матрицы хранятся по столбцам, как `mat4` в GLSL;
- лицевая грань — обход по часовой стрелке, задние грани отсекаются;
- направление источника света — куда он светит;
- текстурные координаты: (0, 0) — левый верхний угол картинки; у тора u идёт вдоль
  кольца, v — вокруг трубки; у пола v = 0 на дальнем от камеры крае (+Z), поэтому
  картинка лежит верхом от зрителя и не отзеркалена.
